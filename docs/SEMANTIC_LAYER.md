# Domain semantic layer

Current: domain-v2 adds a shared prediction-target axis for recognized regression/classification comparisons. Those concepts still do not receive simple-definition rewrites. The contextual comparison route is now promoted; its learned relevance scoring and limits are described in `CONTEXTUAL_COMPARISON.md`. The v1 ablation and decisions below remain historical evidence.

The domain vocabulary is explicit, reviewed data in `src/librarian/domain_concepts.json`, not learned model knowledge. Eight concepts have CZ/EN/PL aliases, separate abbreviations, and typed relations. `semantic_layer.py` validates alias uniqueness and relation targets, and supplies versioned plans with the vocabulary SHA-256. No answer text, source IDs, or document-specific boosts are stored in the vocabulary.

Only full simple definition questions are canonicalized. Negation, examples, comparisons, qualifiers and multipart questions remain unchanged. Abbreviations are separate from aliases: `ML` is not expanded into a generated answer. Explicit acronym requests continue to require matching expansion evidence in the corpus through `acronyms.py`.

Recognition and production rewriting are separate. The initial ablation found that canonical English regression/classification questions can displace a better Czech definition with an MSE derivation or algorithm catalogue. Production therefore enables only deep learning, machine learning, neural networks and overfitting. Regression/classification remain experiment-only; supervised/unsupervised learning are catalogued but not promoted. `analyze(..., production_only=True)` enforces this allowlist. API `semantic_experiment=True` opts into all catalogued definition rewrites for evaluation, not the app default.

Relations are descriptive metadata, not equivalences and not automatic query expansion. In particular deep learning uses neural networks; those concepts are never merged. Existing bounded neural-architecture retrieval remains an explicitly partial-evidence route for deep learning. Other concepts use their canonical query with the same learned retrievers/reranker and evidence thresholds; a vocabulary match alone cannot supply support.

The source course, snapshot, chunks and embedding index remain unchanged. Only rerank mode uses definition plans. E5 and hybrid retain their previous behavior. API `search(..., mode='rerank', semantic_layer=False)` disables concept canonicalization and acronym rules for controlled comparison. Shared source/query-intent priors, algorithm/dataset constraints, candidate neighbors and deduplication remain in both arms: this is a domain-layer ablation, not a pure-model benchmark. Model weights, hardware and index are shared.

Run `.venv/Scripts/python.exe src/librarian/compare_semantic.py` to compare 18 fixed questions (six CZ/EN/PL groups). Full excerpts and decisions are saved locally to `eval/semantic_comparison.local.json` and `.html`; report URL `http://localhost:8765/eval/semantic_comparison.local.html`. Outputs are ignored by Git; fixed questions and script are tracked. Queries become development data after inspection. Identical top-five ordering is expected from canonicalization and is not evidence of answer correctness. Human usefulness judgments and an independent unseen set are still needed before making a quality claim.

Initial result: all six experimental groups have identical top-five IDs across languages, versus none without the layer. This is a mechanical consistency result. Manual Codex spot review: ML remains relevant (English source promoted), neural-network definition preserved, overfitting improves from a variance-specific example to a direct definition; deep learning remains partial. Regression/classification regressions caused the production restriction above. No aggregate usefulness/accuracy score or independent validation is claimed. The frozen initial local experiment predates the production allowlist; its code hashes describe that run.

When extending the vocabulary: add reviewed equivalences only, use a typed relation for broader/narrower/related concepts, preserve ambiguous acronyms separately, add multilingual and negative-intent regression cases, rerun paired retrieval, and inspect actual excerpts for regressions. No automatic synonym harvesting or relation traversal is enabled.

Passage-level follow-up and fresh formulation results: `docs/SEMANTIC_VALIDATION.md`, with all excerpts at `http://localhost:8765/eval/semantic_validation.local.html`. These separate first-passage usefulness from mechanical ordering consistency.
